## Method

- Each program exists five times with the same algorithm and byte-identical output
  (`tools/perfbench/programs/NAME.{ail,c,rs,go,py}`; the larger C-class programs in `tools/perfbench/big/`
  have no Python twin). A column whose output differs from the reference is reported as `DIFF` and left out.
- AIL is `ail build FILE -o EXE` (native code, run directly). C is `gcc -O2` and `clang -O2`
  with `-ffp-contract=off`, so floats match. Rust is `rustc -C opt-level=3` on safe, idiomatic code
  (bounds-checked indexing, `std::collections::HashMap` in wordfreq), ported line for line from the C twin;
  like the C columns it has no `target-cpu` flag. Go is `go build` with its default flags, also ported from
  the C twin (including wordfreq's hand-written FNV-1a hash map). Python is CPython 3 (`python3 -I`), no numpy.
- The C, Rust, Go and Python twins are single-threaded. AIL's native code runs loops the compiler proves
  independent on all cores by default, past a work threshold, with results identical to running them in order
  (ADR 0911). So every AIL row is timed twice: `AIL` with the default thread count and `AIL 1T` with
  `AIL_THREADS=1`, the like-for-like column against the single-threaded twins. A row marked ‡ ran on several
  cores (its 1T time is more than 15% longer). The `AIL / X` columns use the default run and `AIL 1T / X` the single thread.
- Wall time of the whole process, the **median** of the runs shown, on a machine with nothing else running; the
  spread (min–max) of the same runs is under the tables, so a row whose runs differ widely is visible. No best-of
  selection. The tables above are the host in the environment block; any other hosts follow, each with its own environment
  (OS, CPU, compiler versions and the exact flags of every column).
  Each environment block names the commit that host ran.
  The Windows run's version string ends in `-dirty` because its throwaway worktree had one measurement script patched for
  Git bash (`tools/bench/text.py`: it started `./ail`, which Python cannot run on Windows, and compared the text programs'
  output without normalising `\r\n`); no compiler, standard library or runtime file differs from the commit.
  Runs under 0.3 s are within noise of about 10% (`tools/perfbench/README.md`).
- Honest sizes (drag.size.1): publish.sh starts from the size in `NAME.args` and doubles it (adds one for
  fannkuch and binarytrees) until `gcc -O2` takes at least 0.3 s, so no row sits in the noise band. The `size`
  column shows the size every language ran; the reference output is gcc's at that size. The larger programs
  in `tools/perfbench/big/` already run for seconds.

Reproduce (needs gcc, clang, rustc, go and python3; Debian/Ubuntu also python3-venv):

    tools/bench/publish.sh                       # everything on this page
    python3 -I tools/perfbench/race.py --no-run --native --c --rust --go --python --programs tools/perfbench/programs/nbody.ail

## Edit loop: the wait on each agent round

Wall milliseconds, best of the runs shown, from the repository root of the release commit
(`tools/bench/latency.py`, `tools/bench/publish.sh`). `ail check`, `ail context FILE main` and `ail test` are
cold processes each time. `ail build --cold` starts with an empty build cache (`AIL_CACHE_DIR` set to a new directory); `ail build` and
`ail run` (cached) are repeats after the build cache holds the program. The `ail mcp` rows are `ail_check`
calls in one running server: the first call, then the best of the repeats of the same call (mcp.warm.1-4).
`-` means the command did not exit 0 on that host. The programs are `examples/hello.ail`,
`examples/json.ail` and `tools/ailtest/ailtest.ail`; the line count is in brackets.
On Windows each command starts through `ail.cmd` and PowerShell (`ail.ps1`), and that start is inside its time.
