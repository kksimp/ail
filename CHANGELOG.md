# Changelog

AIL is pre-1.0: `v0.MINOR.PATCH`, where MINOR may change the language or std and PATCH only fixes.
Each entry has a hand-written highlights block between two marker comments and a list of merged
pull-request titles under it, generated by `tools/release/changelog.sh`; the rules are in [ADR 1043](docs/decisions/1043-versions-tags-changelog.md).
Seeds keep their dated tags (`seed-YYYY.MM.DD[a-z]`) and are not releases.

## Unreleased (0.2)

<!-- highlights:begin -->
### Highlights

v0.2.0 is the release in which the language was tuned against measured agent runs: fewer first-draft failures, diagnostics that carry the fix, and faster generated code. Agents are still less efficient in AIL than in C today, because models have seen little AIL; [docs/agent-benchmark.md](docs/agent-benchmark.md) says what was measured and how it came out.

**Fixed: two miscompiles that were in v0.1.0.** A `mut` scalar parameter that a function only forwards with `mut` to another function lost the change (`own.param.2`, fixed in [#1335](https://github.com/kksimp/ail/pull/1335)). A `for` loop whose body changed the list it walks from inside a `match`, an `else` or a `?` ran on the live list instead of the snapshot (`expr.loop.4`, fixed in [#1338](https://github.com/kksimp/ail/pull/1338)). Programs built with v0.1.0 that pass a `mut` scalar through, or mutate a list inside such a loop, may have produced wrong results: rebuild them with 0.2.0.

**Language.**
- Functions that never return: `fn usage() never` ends in `io.exit`, and `n := s.to_int() else usage()` compiles ([ADR 1119](docs/decisions/1119-never-return-type.md)).
- One-line `if a then x elif b then y else z` ([ADR 1120](docs/decisions/1120-one-line-if-elif.md)).
- A local may take the name of a function, an imported module or a field until its block ends (`qty := qty(s)`, [ADR 1121](docs/decisions/1121-locals-may-shadow-functions-and-modules.md)).
- Operator traits `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Neg` for any type; `BigInt` takes `+ - * / %` and `<`, and prints with `"{b}"` ([ADR 1124](docs/decisions/1124-arithmetic-operator-traits.md)).
- Every standard module is in scope without `use`, including those written in AIL such as `csv`, `bigint` and `date` ([ADR 1126](docs/decisions/1126-std-modules-in-ail-without-use.md)).
- `x = e else` takes an indented block, as `x := e else` does ([ADR 1128](docs/decisions/1128-else-block-after-assignment.md)).
- `T ! str`: a function may fail with plain text, and `?` passes any error on as its text ([ADR 1129](docs/decisions/1129-str-errors.md)). The standard `Fail` error, `fn f() ! Fail` with `return Fail(msg: "...")`, is the form for a function with no result or one that is not `T ! str` ([ADR 1140](docs/decisions/1140-standard-text-failure.md)).
- New methods `xs.slice(a, b)`, `xs.slice(a)`, `s.slice(a)`, `set.to_list()` ([ADR 1125](docs/decisions/1125-methods-agents-guess.md)).
- `mut m := {}` is a map once `get_or` or a store types it ([ADR 1133](docs/decisions/1133-map-literal-first-use.md), [ADR 1135](docs/decisions/1135-self-read-store-and-text-failure-fixes.md)), and a changed copy of a map entry that is never stored back is a warning ([ADR 1134](docs/decisions/1134-entry-copy-warning.md)).

**Agent tools and auto-fix.**
- `ail check`, `ail build`, `ail run` and `ail test` write the fixes that have exactly one meaning into the file and print `fixed ...`; the rest print `fix: write CODE` ([ADR 1130](docs/decisions/1130-certain-fixes-applied-by-check.md)). The certain fixes cover other languages' spellings (`&&`, `else if`, `??`, `let`), string slips, a missing `mut`, `for i, x in xs`, guessed std names such as `sys.exit` and `str.index_of`, `str ! str`, `else "text"` in a failing function, a held result tested on the next line, and a collection typed by a later use ([ADRs 1138](docs/decisions/1138-string-slip-certain-fixes.md), [1139](docs/decisions/1139-small-agent-slips-certain-fixes.md), [1147](docs/decisions/1147-calc-miss-fixes.md), [1163](docs/decisions/1163-error-type-shape-fixes.md), [1164](docs/decisions/1164-guessed-std-names-fixes.md), [1166](docs/decisions/1166-held-result-one-step-fix.md), [1167](docs/decisions/1167-else-text-and-discarded-value-fixes.md), [1168](docs/decisions/1168-open-collection-later-use-fix.md)).
- The final agent run's first-draft compile misses got fixes and help: a zero-padded `int` (`(a % 100).pad_left(2, '0')`) is rewritten to `"{recv}"` for any receiver, `pad`/`zfill`/`rjust`/`ljust` on an `int` name `"{x:02}"`, a method declared on a built-in type gets help, `BigInt.to_int()` becomes `as_int()`, and `xs.to_list()` on a list drops the call ([ADR 1169](docs/decisions/1169-final-run-first-draft-misses.md)).
- A run reports every error at once: a broken statement or a failed import hides only what depends on it ([ADR 1136](docs/decisions/1136-every-error-in-one-run.md)).
- `ail ask std` prints what each answer does and understands `stderr`, `argv` and `exit code` ([ADR 1123](docs/decisions/1123-ail-ask-std-answers-in-one-step.md)). `ail explain std.io` lists a rule family and `ail explain exit` finds the rules naming a word.
- Diagnostics name the standard function an agent guessed, the `pub` lines a private field needs, and the file move a flat module needs. Key-function errors agree ([ADR 1122](docs/decisions/1122-key-function-errors-agree.md)).
- The language cards were rewritten from the agent-benchmark transcripts: the full card stays within 16,000 tokens, with a short core card and `llms-full.txt`. `AGENTS.md` from `ail new` and the `ail mcp` `initialize` reply open with the same two lessons ([ADR 1137](docs/decisions/1137-agent-lessons-in-kit-and-mcp.md)).

**Speed.** Generated code is faster on the loops and data structures the benchmarks use: element-wise loops in two, four and `int` lanes ([ADRs 1142](docs/decisions/1142-element-wise-vector-loops-and-list-alias-classes.md), [1144](docs/decisions/1144-four-element-vector-passes.md), [1145](docs/decisions/1145-int-lanes-with-an-overflow-mask.md)), branch-free selects ([ADRs 1141](docs/decisions/1141-branch-free-selects-with-guards.md), [1150](docs/decisions/1150-select-chains-index-selects-unsigned-division.md), [1151](docs/decisions/1151-conditional-stores-as-selects.md), [1162](docs/decisions/1162-conditional-sums-as-checked-selects.md)), lists that keep structs in place ([ADRs 1149](docs/decisions/1149-structs-kept-in-place-in-lists.md), [1156](docs/decisions/1156-structs-with-pointers-kept-in-place.md); `ail perf --explain` reports them, [ADR 1161](docs/decisions/1161-in-place-report-and-field-cap.md)), map lookups compiled into the caller ([ADR 1148](docs/decisions/1148-map-lookups-compiled-into-the-caller.md)), split loops with a parallel head ([ADR 1143](docs/decisions/1143-split-loops-parallel-head.md)), retuned thresholds for the worker pool ([ADRs 1155](docs/decisions/1155-builder-loop-pool-threshold.md), [1157](docs/decisions/1157-counted-loops-need-more-work-for-the-pool.md)), a faster collector sweep ([ADR 1165](docs/decisions/1165-sweep-skips-unreached-pages.md)), keyed string sort ([ADR 1159](docs/decisions/1159-string-sort-keyed-pairs.md)), arm64 multiply-add ([ADR 1154](docs/decisions/1154-arm64-multiply-add.md)), radix sort for `int` and `float` lists, and faster float printing and parsing and text and line reads. The numbers are in [docs/benchmarks.md](docs/benchmarks.md), regenerated for this release, with the method, the known gaps and the commands that reproduce them. The C twins are single-threaded and AIL auto-parallelizes; that page is the only source for numbers.

**Changed behaviour.** A program written for v0.1.0 may need these changes:
- `ail check`, `build`, `run` and `test` now edit the source file when a fix has one meaning. Read the file again before editing it by hand, and keep the program under version control.
- `BigInt.cmp` returns `Ordering`, not -1, 0 or 1; `BigInt` now implements `Ord` and `ToStr`.
- A user type named `Add`, `Sub`, `Mul`, `Div`, `Rem` or `Neg` is an error (`mod.unit.1`) with a rename fix. A program that declares its own `Fail` keeps using it.
- A `use std.NAME` line is no longer needed for any standard module and may be removed.

**Known limits.**
- No debug info yet (`ail build -g`, DWARF and PDB, is planned for a later release): no debugger can step an AIL program.
- Windows ARM64 is untested. Linux ARM64 is checked under emulation only.
- The TLS and cryptography are AIL's own and have had no third-party audit ([SECURITY.md](SECURITY.md)).
- There is no package registry, by decision: dependencies are git URLs pinned in `ail.lock`.
- `std.audio` is young. VP9 profiles 1-3 and a TLS server are not included.
- No editor extension is on a marketplace yet.
- Agents still need more tries in AIL than in C on some tasks; see [docs/agent-benchmark.md](docs/agent-benchmark.md).
- The planned list for the next release is in [docs/roadmap.md](docs/roadmap.md).

## v0.1.0 - 2026-11-15

<!-- highlights:begin -->
### Highlights

AIL (AI-First Language, "ale") is a native, garbage-collected, memory-safe systems language built so that people and AI agents are both first-class programmers. v0.1.0 is the first public release: the compiler is written in AIL and builds itself from a published seed.

**Language.** Mutable value semantics: values are independent, `mut` is marked at call sites, shared mutation goes only through `ref T`. Errors are values (`error` types, `?`, `else`). Traits and generics, enums with data and `match`, tasks and channels without async/await, `defer`, `requires`/`ensures` contracts that tools can check or fuzz, and effects and capabilities that `ail check --deny` can enforce. Calls to variadic C functions such as `printf` ([ADR 1031](docs/decisions/1031-variadic-c-calls.md)). One canonical format (`ail fmt`).

**Toolchain.** A native compiler, linker and runtime written in AIL, with no LLVM and no C. It runs on macOS ARM64, Linux x86-64 and Windows x86-64, builds optimised code with auto-parallel loops and SIMD, and has a stop-the-world collector. The HTTP server waits on idle connections in an epoll set on Linux, a kqueue set on macOS and a completion port on Windows. Its memory model is specified in [spec chapter 06](docs/spec/06-memory.md). The Mac, Linux and Windows gates run the same suite list before every release.

**Agent tools, one loop.** `ail task start`, `ail context`, `ail edit`, `ail check --fix`, `ail test --affected`, `ail task verify`, `ail task finish`. `ail ask` answers who calls what, `ail explain RULE` gives the text of any rule a diagnostic cites, `ail card` prints the language card, `ail review` summarises a change by meaning, `ail try` checks a patch in memory, and `ail mcp` and `ail lsp` serve the same tools to agents and editors. Diagnostics are structured and cost-bounded with `--budget`. `ail perf --explain FN FILE` says, per loop, which bounds checks stayed and why, what was vectorised or parallelised, and which calls were not inlined ([ADR 1021](docs/decisions/1021-perf-explain.md)). A running app can offer its `@tool` methods to agents as typed actions through `ail attach mcp` ([ADR 0986](docs/decisions/0986-app-tools-and-attach-mcp.md)). `ail help` lists every command with its usage and rules, and `ail doctor` reports what is wrong with an install ([ADRs 1057](docs/decisions/1057-ail-help.md), [1058](docs/decisions/1058-ail-on-path-and-doctor.md)). Shipped commands call no Unix tools, so they behave the same on Windows ([ADR 1059](docs/decisions/1059-no-unix-tools-in-shipped-commands.md)). A VS Code extension and grammar are in `tools/vscode/`, installed locally (not on the marketplace).

**Standard library by area.**
- Text and data: strings, `bytes`, `std.json`, `std.regex` (linear time), `std.path`, `std.time`.
- Files, processes and OS: `std.fs`, `std.env`, `std.io`, `std.proc`, `std.term` (raw input, cursor and colour for text interfaces); `fs.trash` moves a file or directory to the user's trash (the Recycle Bin on Windows) instead of deleting it.
- Network: `std.net` HTTP/1.1 client, HTTPS over in-house TLS 1.3, an HTTP server.
- Crypto and compression: `std.hash`, `std.compress` (DEFLATE, gzip, zip), in-house crypto.
- Media: `std.audio` (FLAC, Opus CELT, SILK and hybrid, streaming playback on macOS, Linux and Windows), `std.video.vp9`, `std.media.webm`.
- Apps and graphics: `std.app` windows, `std.gfx` real-time frame loop, gamepad input.
- Numeric: `std.tensor` on the CPU.

**Speed.** AIL compiles to fast, efficient native code: optimised, with auto-parallel loops and SIMD. [docs/benchmarks.md](docs/benchmarks.md) measures it against C, Rust, Go and Python on macOS, Linux and Windows, with the method and the commands that reproduce every number; that page is the only source for them. Its known gaps (`fasta`, `lzr`) are planned for 0.1.1.

**Known limits.**
- No debug info yet (`ail build -g`, DWARF and PDB, is planned for 0.2): no debugger can step an AIL program.
- Windows ARM64 is untested. Linux ARM64 is checked under emulation only.
- The TLS and cryptography are AIL's own and have had no third-party audit ([SECURITY.md](SECURITY.md)).
- There is no package registry, by decision: dependencies are git URLs pinned in `ail.lock`.
- The first run builds the compiler from the seed; there is no prebuilt `ail` per release yet.
- `std.audio` is young. VP9 profiles 1-3 and a TLS server are not included.
- No editor extension is on a marketplace yet.
- The planned list for the next release is in [docs/roadmap.md](docs/roadmap.md).
