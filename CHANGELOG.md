## v0.1.0 - 2026-11-15

<!-- highlights:begin -->
### Highlights

AIL (AI-First Language, "ale") is a native, garbage-collected, memory-safe systems language built so that people and AI agents are both first-class programmers. v0.1.0 is the first public release: the compiler is written in AIL and builds itself from a published seed.

**Language.** Mutable value semantics: values are independent, `mut` is marked at call sites, shared mutation goes only through `ref T`. Errors are values (`error` types, `?`, `else`). Traits and generics, enums with data and `match`, tasks and channels without async/await, `defer`, `requires`/`ensures` contracts that tools can check or fuzz, and effects and capabilities that `ail check --deny` can enforce. Calls to variadic C functions such as `printf` ([ADR 1031](docs/decisions/1031-variadic-c-calls.md)). One canonical format (`ail fmt`).

**Toolchain.** A native compiler, linker and runtime written in AIL, with no LLVM and no C. It runs on macOS ARM64, Linux x86-64 and Windows x86-64, builds optimised code with auto-parallel loops and SIMD, and has a stop-the-world collector. The HTTP server waits on idle connections in an epoll set on Linux, a kqueue set on macOS and a completion port on Windows. Its memory model is specified in [spec chapter 06](docs/spec/06-memory.md). The Mac, Linux and Windows gates run the same suite list before every release.

**Agent tools, one loop.** `ail task start`, `ail context`, `ail edit`, `ail check --fix`, `ail test --affected`, `ail task verify`, `ail task finish`. `ail ask` answers who calls what, `ail explain RULE` gives the text of any rule a diagnostic cites, `ail card` prints the language card, `ail review` summarises a change by meaning, `ail try` checks a patch in memory, and `ail mcp` and `ail lsp` serve the same tools to agents and editors. Diagnostics are structured and cost-bounded with `--budget`. `ail perf --explain FN FILE` says, per loop, which bounds checks stayed and why, what was vectorised or parallelised, and which calls were not inlined ([ADR 1021](docs/decisions/1021-perf-explain.md)). A running app can offer its `@tool` methods to agents as typed actions through `ail attach mcp` ([ADR 0986](docs/decisions/0986-app-tools-and-attach-mcp.md)). `ail help` lists every command with its usage and rules, and `ail doctor` reports what is wrong with an install ([ADRs 1057](docs/decisions/1057-ail-help.md), [1058](docs/decisions/1058-ail-on-path-and-doctor.md)). Shipped commands call no Unix tools, so they behave the same on Windows ([ADR 1059](docs/decisions/1059-no-unix-tools-in-shipped-commands.md)). A VS Code extension and grammar are in `tools/vscode/`, installed locally (not on the marketplace).

**Standard library by area.**
- Text and data: strings, `bytes`, `std.json`, `std.regex` (linear time), `std.path`, `std.time`.
- Files, processes and OS: `std.fs`, `std.env`, `std.io`, `std.proc`, `std.term` (raw input, cursor and colour for text interfaces); `fs.trash` moves a file or directory to the user's trash (the Recycle Bin on Windows) instead of deleting it.
- Network: `std.net` HTTP/1.1 client, HTTPS over in-house TLS 1.3, an HTTP server.
- Crypto and compression: `std.hash`, `std.compress` (DEFLATE, gzip, zip), in-house crypto.
- Media: `std.audio` (FLAC, Opus CELT, SILK and hybrid, streaming playback on macOS, Linux and Windows), `std.video.vp9`, `std.media.webm`.
- Apps and graphics: `std.app` windows, `std.gfx` real-time frame loop, gamepad input.
- Numeric: `std.tensor` on the CPU.

**Speed.** AIL compiles to fast, efficient native code: optimised, with auto-parallel loops and SIMD. [docs/benchmarks.md](docs/benchmarks.md) measures it against C, Rust, Go and Python on macOS, Linux and Windows, with the method and the commands that reproduce every number; that page is the only source for them. Its known gaps (`fasta`, `lzr`) are planned for 0.1.1.

**Known limits.**
- No debug info yet (`ail build -g`, DWARF and PDB, is planned for 0.2): no debugger can step an AIL program.
- Windows ARM64 is untested. Linux ARM64 is checked under emulation only.
- The TLS and cryptography are AIL's own and have had no third-party audit ([SECURITY.md](SECURITY.md)).
- There is no package registry, by decision: dependencies are git URLs pinned in `ail.lock`.
- The first run builds the compiler from the seed; there is no prebuilt `ail` per release yet.
- `std.audio` is young. VP9 profiles 1-3 and a TLS server are not included.
- No editor extension is on a marketplace yet.
- The planned list for the next release is in [docs/roadmap.md](docs/roadmap.md).
