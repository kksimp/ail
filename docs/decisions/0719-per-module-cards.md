# 0719. `ail api --card --module NAME` prints one module's card

- **Status:** Accepted
- **Date:** 2026-10-21
- **Decided by:** AI (delegated, ADR 0076; lane 227)
- **Topic:** Tools (lane 227)
- **Spec rules:** api.card.6 (new); api.card.3 wording unchanged
- **Amends:** none; [ADR 0310](0310-ail-api-card-format.md) and [ADR 0311](0311-ail-api-card-budget-and-trimming.md) still hold for the whole-package card

## Context

A package card at 2,000 tokens drops to names only for every tool package
written in AIL (garlic, the PDF viewer, the compiler; see
[docs/design/cards/README.md](../design/cards/README.md)). The signatures do not
fit, so an agent that needs one module must read the whole package at the
budget that loses it. The brief for lane 227 asks for a card per module.

## Options considered

1. **One card file per module, regenerated by a shell loop.** Needs no code, but
   the module boundary and the naming rule live only in the loop, and nothing
   checks them. Rejected: the freshness test could not tell a missing module card.
2. **`--module NAME` on the existing command, filtering the built card.** The
   card already holds the modules sorted and the same trimming levels, so a filter
   is a few lines. The output format and levels are unchanged. Chosen.
3. **A separate `ail api --module` command.** Duplicates the card command's
   budget and JSON handling. Rejected.

## Decision

1. `ail api --card --module NAME [--budget N] [--json] PATH` prints the card of
   one module, trimmed exactly as api.card.3 trims a package card. `NAME` is a
   module name as the index lists it; `(root)` names the package's own module.
2. The entry, manifest and examples appear only on the root module's card. The
   tests on a module card are those of that module.
3. An unknown module is exit code 2 with a message that names the index command.
4. `ail api --card` without `--module` is unchanged.

## Measured sizes

At a 2,000-token budget every module of the six committed packages fits at some
level except `tools/edit`'s root module (149 items). Its signatures do not fit,
so its card gives the item count and no items. Splitting that module is a change
to `tools/edit`, not to the card command.

## Ranking fix (same change)

Choosing the richest level (ADR 0703) counted the trailer's tokens, and a deeper
level's trailer lists more dropped items, so it could outrank a fuller level.
The ranking now counts content only; the budget check still counts the whole
card. The effect on the committed cards: `std.md` loses a trailer that said
`trimmed to fit` when its full card already fit. Nothing else changed.

## Consequences

- The committed module cards in `docs/design/cards/<package>/` are checked by
  `cargo test --test api_card`.
- A module card can drop its package header lines (entry, manifest, examples),
  so an agent reads them from the index or the package card.
