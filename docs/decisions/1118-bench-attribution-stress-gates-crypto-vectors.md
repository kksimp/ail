# 1118. Benchmark attribution, stress gates and crypto vectors for 0.1.1

- **Status:** Accepted
- **Date:** 2026-11-15
- **Decided by:** AI (delegated, [ADR 0076](0076-delegated-decisions.md)); answers items 6 to 8 and the cheap stress checks of the external review of 2026-11-15
- **Topic:** 11 — Concurrency; 14 — Tooling
- **Builds on:** [ADR 0911](0911-default-automatic-parallel-loops.md), [ADR 0842](0842-mac-first-gate.md), [ADR 1074](1074-c-structs-by-value-and-callbacks.md), [ADR 0360](0360-in-house-tls-for-std-net.md)

No compiler, runtime or language change: tooling, tests and data only.

## Context

The review found four weaknesses that need evidence, not features:

1. `docs/benchmarks.md` reported best-of-5 and mixed parallel and single-thread ratios. `matmul`, `spectralnorm` and
   `mandelbrot` ratios come mostly from AIL using every core against single-threaded C, Rust, Go and Python twins.
2. The C ABI fixtures (`tools/ffi-abi`, ADR 1074) and the heap check (`AIL_GC_VERIFY`) existed but no gate ran them.
   Nothing stressed the collector or the schedulers on purpose.
3. The in-house crypto (ADR 0360) is checked against OpenSSL vectors we generated ourselves; no independent set,
   no strict DER cases, no negative AEAD cases, and "constant time" was claimed but not measured.

## Decision

**Benchmarks.** `race.py` has `--native-1t`: it times the same executable with `AIL_THREADS=1` (column `native1t`).
`publish.sh` always passes it. `publish.py` reports the **median** of the runs, not the minimum, adds `AIL 1T` and
`AIL 1T / X` columns, marks a row ‡ when its 1T time is more than 15% above its default time, and prints a table of
min–max spread per column. The environment block lists the OS, the exact flags of every column, the tool versions and the
load at the start. Ratios stay neutral (below 1 means AIL is faster); no row is described as matching another
language. The page is regenerated by the next run on the three hosts, not edited by hand.

**Gate.** Two new suites in `tools/gate/suites.txt`:

- `ffi_abi` runs `tools/ffi-abi/run.sh` (`run.ps1` on Windows).
- `stress` builds each `tests/stress/*.ail` once (self-checking programs with fixed totals, so the setting does not
  reach the compiler) and runs it by default, with `AIL_THREADS=1`, with `AIL_GC_VERIFY=1` and with the strided form
  `AIL_GC_VERIFY=0,100000000,997`; the small concurrent program also runs under `ail run --schedule=random:1` to `8`. It also runs every `par_*` case that has only an `.out`
  with `AIL_THREADS=1`, so a loop that gives the right answer only on one thread, or only in parallel, is red.

There is no collect-every-N mode: the programs allocate enough to collect many times, and the heap check runs at each
collection. A forced-collection switch would be a runtime change and is left for later.

**Crypto.** Kept in-house. Added:

- Project Wycheproof (C2SP/wycheproof, Apache-2.0) vectors for AES-GCM, ChaCha20-Poly1305, X25519, HMAC-SHA-256,
  HKDF-SHA-256, ECDSA P-256 and P-384 (strict DER) and RSA PKCS#1 v1.5 and PSS, converted by
  `tools/native-tls/wycheproof.py` into `tests/data/net/crypto/wycheproof*.txt` and run by `prim-check.sh` in the `crypto`
  suite. `tlsprim_verify` now reads ECDSA signatures with the TLS client's own parser (`x_ecdsa_sig`) instead of a
  looser copy. Cases whose result is `acceptable` are left out. A failure is a defect in AIL's code or a case the
  gate names, not a reason to drop the case.
- `tools/native-tls/timing-check.sh`: a dudect-style test (fixed against random secrets, random order, percentile
  crops, Welch's t, leak above 10) of `ct_eq`, X25519, ChaCha20-Poly1305, AES-GCM and Poly1305, with an early-exit
  comparison as a control that must be flagged. It is not in the gate: timing on a busy or virtual machine gives false
  alarms. It runs on an idle host, on a schedule, with the run pinned to one core where `taskset` exists.

## Rejected alternatives

- **Keep best-of and add a column.** Best-of hides the spread; the median with the range is what readers need.
- **Hosted audited crypto** (the review's first choice). Contradicts ADR 0360 and ADR 0009; the gap is closed with
  external vectors and measurement instead, and the page still says there has been no audit.
- **Put the timing test in the gate.** The gate runs on VMs that share cores; a false alarm there blocks every merge.
- **A collect-every-N runtime switch now.** Useful, but a runtime change that needs its own review; the existing heap
  check over allocation-heavy programs gives most of the value.
- **Wycheproof via a hosted dependency at test time.** The gate must not need the network; the converted vectors are
  committed with the SHA-256 of each source file.
- **All Wycheproof files.** 3072-bit RSA, 192-bit AES keys and truncated tags add size and no new code path.

## Consequences

The gate gains two suites and the `crypto` suite grows by about 3,000 cases. A host that fails a Wycheproof case shows
a real bug, to be fixed in the primitive. Benchmark pages generated before this change lack the 1T column and show
min where the new ones show the median; hosts rendered together should be re-run with the same `publish.sh`.
