# 1203. Certain fixes for the first-draft habits: error set, `?`, float patterns

- **Status:** Accepted
- **Date:** 2026-11-26
- **Decided by:** Designer (Kaleb approved the recommendation of the third Opus trial, 2026-11-26); built by AI under [ADR 0076](0076-delegated-decisions.md). Diagnostics and fixes only, no language change
- **Topic:** 22 — Tools
- **Spec rules:** [err.type.3](../spec/08-errors.md), [err.use.1](../spec/08-errors.md), [expr.match.7](../spec/05-expressions.md), [fix.auto.1](../spec/22-tools.md), [trait.op.1](../spec/10-traits.md)
- **Amends:** [ADR 1199](1199-public-error-set-fix.md) (its "the fix is a guess" and its float-pattern help), [ADR 1166](1166-held-result-one-step-fix.md)

## Context

The third Opus trial (main e9943baa) left four of eight first drafts failing, each on a habit whose answer the
compiler already printed as a `fix:` line: `+` on text, the error set of a public function, `?` on a `wait`, and a
float literal in a pattern. `ail check --fix` wrote them; plain `ail check`, which the agent runs first, wrote
only the certain ones, so each cost a cycle and a read of the help. The trial estimated that making them
certain lets 3 of the 4 failing drafts pass their first check.

## Decision

All four are certain fixes (`fix.auto.1`), so `ail check`, `build`, `run` and `test` write them:

- **`+` on text.** Already certain (ADR 1175, ADR 1199); a gate case now covers it with the others.
- **err.type.3.** The fix that writes the inferred error set (`! fs.IoError`, `str ! Empty | TooLong`) is certain. It is
  written into the module's file, where the report is. ADR 1199 left it a guess for fear of setting public
  signatures unread; the designer chose speed of the first check over that review, and the set is the exact one the
  checker inferred.
- **err.use.1.** The `?` fix is certain when the function's error type admits the errors. When it doesn't, the
  signature-and-`?` fix is certain for `main` only, which no function calls; for any other function it stays a
  guess, because a new `! E` changes its callers.
- **expr.match.7, float literal.** The parser's report now carries a fix, anchor `float_guard`: the arm's float
  literals become names (`fv`, `fv2`, a name no word of the line uses) and one guard tests them
  (`Pair(Lit(1.0), Lit(2.5)) =>` is `Pair(Lit(fv), Lit(fv2)) if fv == 1.0 and fv2 == 2.5 =>`). The edit is dropped when
  the arm has a guard or alternatives, a literal follows `-` or `.`, or the line is not a plain arm; the help stays.

## Options considered

- **Leave err.type.3 a guess (ADR 1199):** rejected by the designer.
- **Certain `! E` for every function in the `?` fix:** rejected; callers then fail, and the cascade rewrites code
  the author did not touch. `main` has no callers.
- **Float equality in patterns:** a language change, rejected in ADR 1199.
- **A list of task handles that must be waited:** not part of this change; the designer has not approved it.

## Consequences

- `compiler/check/errfix.ail`, `compiler/check/relate.ail` (certain fixes); `compiler/fix/floatguard.ail` (new),
  one line each in `compiler/fix/resolve.ail`, `edit.ail`, `sure.ail`; `compiler/syntax/parse.ail` (the report).
- Mistakes pairs `float_pattern_guard` and `main_wait_unhandled`; gate case `auto_fix_habits`.
- `compiler/explain/fixable.txt` gains `expr.match.7`; the explain, fix and api goldens are regenerated by the runner.
- Not built in the cloud: the runner builds and runs the gate.
