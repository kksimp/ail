# 0110. `bool` with `true` and `false`; conditions must be `bool`

- **Status:** Accepted
- **Date:** 2026-10-04
- **Decided by:** AI (delegated, [ADR 0076](0076-delegated-decisions.md))
- **Topic:** 4 — Type system; 2 — Core syntax (expressions)
- **Spec rules:** [type.bool.1](../spec/04-types.md), [expr.if.2](../spec/05-expressions.md)

## Deciding criterion

Token usage **ties** (`true` and `false` are one token each in every tokenizer
measured). **AI understanding** decides "no truthiness": `if count` or
`if name` would hide a comparison, so every condition is an explicit `bool`.

## Decision

1. `bool` is the type of `true` and `false`.
2. Conditions of `if`, `elif` and `while`, and the operands of `and`, `or`
   and `not`, must have type `bool`. There's no implicit truthiness.

## Rejected alternatives

- Truthiness (`if count`, `if name`): rejected because it hides a comparison, so every condition is an explicit `bool`. Token usage ties.
