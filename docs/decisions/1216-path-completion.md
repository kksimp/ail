# 1216. Complete `std.path`: abs, clean, rel, parts, join_all, with_ext, split_ext, match, is_abs, expand_home

- **Status:** Accepted
- **Date:** 2026-11-26
- **Decided by:** AI (delegated, [ADR 0076](0076-delegated-decisions.md)); the designer asked for the standard library to be filled out on 2026-11-26
- **Topic:** 21 — Standard library architecture
- **Spec rules:** [std.path.6–14](../spec/17-std.md); amends std.path.1
- **Extends:** [ADR 0253](0253-std-path.md), [ADR 0630](0630-is-empty-and-path-stem.md), [ADR 0281](0281-std-fs-walk-glob-metadata.md)

## Context

`std.path` had five functions (`dir`, `base`, `ext`, `stem`, `join`). The agent trials and the corpus programs
rewrote the rest by hand: collapse `..`, make a path absolute, find the way from one directory to another, swap an
extension, split a path into its parts, test a name against `*.ail`, expand `~`. None of this needs the file system,
except the working directory and the home directory.

## Decision

- Ten functions, all in `compiler/rt/native/path.ail`, each a call of the runtime (`mir/lower_path.ail` names them;
  `split_ext` builds its pair from two calls): `is_abs`, `clean`, `abs`, `parts`, `join_all`, `rel`, `with_ext`,
  `split_ext`, `match`, `expand_home`. Rules std.path.6–14.
- Text is read with every separator as `/` (Windows `\` too) and rebuilt with `/`, as `join` already does. One code
  path serves every target; a Windows API accepts `/`.
- `clean` is lexical (no links resolved), so it can be wrong across a symbolic link; the spec says so. `rel` is `none`
  when no relative path exists instead of guessing (different roots, an unresolvable `..` in `base`).
- `abs` and `expand_home` carry the `env` effect (the checker's effect row); the rest have none (std.path.1).
- `with_ext` and `split_ext` use `ext` without the dot, like `ext` and `stem`; `with_ext` ignores a leading dot.
- `match` shares `fs.glob`'s matcher (`glob_match` in `rt/native/glob.ail`, the old `glob_wildcard` is `glob_match`
  without classes) and adds `[abc]`, `[a-z]`, `[!abc]` for `path.match` only. `fs.glob` keeps `[` as an ordinary
  character, so existing patterns don't change meaning. A class matches one ASCII byte.
- `**` and a leading `.` follow `fs.glob`: `**` doesn't cross a dotted name and, last, needs at least one name.
- Windows drive-relative paths (`C:x`) are cleaned but not made absolute; Windows root comparison in `rel` ignores
  case, component comparison doesn't.
- The native tests are `tests/native/run/path_more.ail` with its golden. They use `/` paths only so every host
  prints the same. No new syntax.

## Rejected alternatives

- **A `Path` type.** `std.path` works on `str` (ADR 0253); a wrapper type makes every `fs` call convert.
- **`rel` returning the absolute `target` when there is no relative path** (Python raises, Go returns an error): a
  value that is not what the name says hides the failure; `none` is checked.
- **`clean` resolving links** (`filepath.EvalSymlinks`): it reads the disk, so it would need an effect and could fail.
- **Putting classes into `fs.glob`.** A file named `a[1].txt` matches its own name today; changing that is a
  behaviour change that needs its own decision.
- **Output with `\` on Windows.** `join` writes `/`; two separators in one module would surprise a program that
  mixes them.
- **`split_ext` with the dot in the extension** (Python's `splitext`): `ext` has none; one rule for `ext`, `with_ext`
  and `split_ext` is easier to keep in mind.

## Consequences

`std.path.1` now names the two functions with an effect. The card lists the new functions from the checker's
signatures (regenerated by the integrator). Not tested here: the Windows behaviour (the gate on `ail-win` covers the
shared code path, with the `/`-only test).
