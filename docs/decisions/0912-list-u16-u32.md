# 0912. Native `List[u16]` and `List[u32]` hold two and four bytes per element

- **Status:** Accepted
- **Date:** 2026-10-25
- **Decided by:** AI (delegated, ADR 0076)
- **Topic:** 23 — Compiler architecture
- **Amends:** [ADR 0907](0907-list-u8-one-byte.md)

## Context

ADR 0907 made a `List[u8]` one byte an element. Programs that keep large tables
of 16- and 32-bit counters (the context-mixing tables of the Clove compressor)
still pay 8 bytes an element, so most of a prediction step is cache misses. The C
versions use `u16` and `u32` tables and run several times faster.

## Decision

`Ty.elem_bytes()` is 1 for `bool` and `u8`, 2 for `u16`, 4 for `u32` and 8 for
every other type. Signed narrow types (`i8`, `i16`, `i32`) and `u64` keep 8: a
narrow signed element needs a sign-extending load, which no program asked for.
Semantics do not change; a list's capacity is not observable.

- Width follows the **list's element type**, never the type of the value pushed
  or stored: a push names its width in the callee (`rt.list_pushb`,
  `rt.list_pushw`, `rt.list_pushd`) and the code generators inline it by that
  name; an indexed store copies the value into a value of the element type
  first (`Lower.slot_val`), because `x.to_u16()` keeps its source's SSA type.
  Both were bugs in the `u8` rollout.
- Loads zero-extend and stores keep the low bytes (`movzx`/`mov r32`,
  `ldrh`/`ldr w`; `mov16`/`mov32`, `strh`/`str w`). Values must already be in
  range, as for `u8`.
- Runtime functions that take an element size (`list_get_word`,
  `list_set_word`, copy, slice, extend, insert, reverse, `contains`, `index_of`,
  equality, `flatten`, `windows`, `chunks`) handle 1, 2, 4 and 8 bytes.
  Operations that read words (`sort`, `sum`, `min`, `max`, `<`, `cmp`, building
  a set) widen first (`rt.list_widen(xs, size)`) and `sort` narrows back
  (`rt.list_narrow_into`), as for `u8`.
- Whole-list output (`rt.out_list_u8`, `_u16`, `_u32`; `out_list_deep` leaf
  kinds 6, 7, 8) and set and map key and value lists (`rt.map_keys_n`,
  `rt.map_values_n`, which replace the `_bool` variants) take the size.
- `rt.fill` stays for widths 1 and 8; 2 and 4 take the generic loop.
- Narrow list data is pointer-free (heap kind 11) for every width below 8.

## Rejected alternatives

- **Signed narrow lists in the same change:** need sign-extending loads and
  stores in four code paths; no user yet.
- **A packed array type for tables:** a second collection with its own
  methods; `List` already has them.
- **Choosing width from the stored value's type:** wrong whenever a converted
  value keeps its source's type; it corrupted the heap twice for `u8`.
