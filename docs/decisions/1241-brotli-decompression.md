# 1241. `compress.unbrotli`: an in-house Brotli decoder

- **Status:** Accepted
- **Date:** 2026-11-27
- **Decided by:** AI (delegated, [ADR 0076](0076-delegated-decisions.md)), within the designer's std push of
  2026-11-26 (std gap plan, wave 3: "Brotli and zstd decompression for HTTP and archives") and the in-house
  rule for codecs ([ADR 0009](0009-custom-tooling-policy.md), [ADR 0010](0010-no-llvm-backend.md))
- **Topic:** Standard library, `std.compress`
- **Spec rules:** [std.compress.12-13](../spec/17-std.md)

## Context

Web servers answer `Accept-Encoding: br` with Brotli (RFC 7932), and some archive and font formats carry it.
`std.compress` had DEFLATE, gzip, zlib and zip only, so an agent that met a Brotli body had no way to read it short
of a C library, which the in-house rule excludes. A decoder is self-contained: the format plus three fixed tables
(a 122,784-byte static dictionary, 121 word transforms, the context lookup).

## Decision

`compress.unbrotli(data bytes) bytes ! compress.CompressError`, a built-in call like `inflate`, with no effects.

- The decoder is `compiler/rt/native/brotli.ail`, written from the RFC. It keeps the whole output in one growing
  bytes object, so back references read the output directly and no ring buffer is needed. Prefix codes decode
  through a 256-entry table for codes up to 8 bits and a canonical walk for longer ones.
- The fixed data is `compiler/rt/native/brotli_data.ail`, generated by `tools/native/gen_brotli.py` from the Brotli
  project's copies of the RFC appendices (MIT licence, recorded in NOTICE). The generator checks the dictionary's
  SHA-256 against the RFC. The dictionary is stored DEFLATE-compressed and base64-encoded (77 KB of source instead
  of 164 KB as base64 alone); the runtime inflates it with `compress.ail`'s inflater on a stream's first dictionary
  reference and keeps it in runtime global slot 68 for the rest of the process. Programs that never call
  `unbrotli` link none of it (ADR 0393).
- Failures use the existing `CompressError` kinds: `corrupt` with one message per defect (std.compress.13),
  `too_big` past 2^30 bytes (std.compress.4), and `unsupported` for the large-window extension, which is not part
  of RFC 7932.
- Trailing bytes after the stream fail, as they do for `inflate`, so a truncated or concatenated body is reported
  instead of silently cut.

## Options considered

- **Written in AIL under `std/`:** rejected. `compress` is a built-in module and the decoder is a hot byte loop; the
  plan's rule puts what needs real speed in the runtime.
- **Dictionary as raw base64 or hex:** rejected for size: 164 KB or 246 KB more runtime source parsed on every
  build, against 77 KB.
- **Inflating the dictionary on every call:** rejected; it costs several milliseconds per HTTP body. The global slot
  makes it once per process.
- **An encoder (`brotli`):** not now. Decoding is what HTTP clients and archives need; gzip remains the encoder.
- **Sending `Accept-Encoding: br` from `net`:** left to a follow-up in the `net` lane; it changes every request's
  bytes and the recorded HTTP tests.
- **Large-window Brotli:** rejected; it is a separate, non-RFC extension that servers do not send to browsers.
