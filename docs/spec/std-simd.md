# Standard library: `std.simd` lane vectors

Chapter key: `std`

> **Status:** Draft (ADR 1014). Written in AIL in `std/simd/simd.ail`
> (generated by `tools/simd/gen.py`) and tested by `tests/cases/std_simd.ail`.
> Stage 1: the types and every operation, with the lane-by-lane meaning below
> on every target. Stage 2, packing the lanes into vector registers (SSE/AVX2 on
> x86-64, NEON on ARM64), is the later step of ADR 1014 and changes no result.

**std.simd.1** — `use std.simd` provides eight lane vector types, structs of
their lanes: 128-bit `F32x4`, `F64x2`, `I32x4` and `I64x2`, and 256-bit
`F32x8`, `F64x4`, `I32x8` and `I64x4`. `F32`, `F64`, `I32` and `I64` name the
lane type `f32`, `float`, `i32` and `int`; the number after `x` is the lane
count. `T.splat(x)` has every lane `x`, `T.zero()` every lane zero, `T.load(xs,
at)` takes the lanes from `xs[at]` on (a list too short traps like any index),
`v.to_list()` returns the lanes and `v.store(mut xs, at)` writes them to
`xs[at]` on. A vector is a value: it is copied, compared with `==` by its
lanes, and never changed in place. *(ADR 1014)*

**std.simd.2** — `v.lane(i)` is lane `i` and `v.with_lane(i, x)` a copy with
lane `i` set to `x`. A lane number outside `0..lanes` traps with `std.simd.2`.
*(ADR 1014)*

**std.simd.3** — Every operation below is defined lane by lane: lane `i` of
the result depends only on lane `i` of each operand, except `sum` (std.simd.8).
A lane is computed exactly as the scalar operation on its type does it: IEEE
single or double precision for `f32` and `float`, with no fused multiply-add and
no flush of subnormals, and the sized integer's width for `i32`. A program
therefore prints the same on every target and at either width. *(ADR 1014)*

**std.simd.4** — `add`, `sub` and `mul` (not `mul` of `I64x2` and `I64x4`, which
the vector units of both baselines lack), and for the float types `div`,
`sqrt`, `abs` and `neg`; for the integer types `add`, `sub` and `neg` *wrap* in
two's complement, so they never trap (type.num.12). `a.add(b)` is lane `i` of `a`
plus lane `i` of `b`. *(ADR 1014)*

**std.simd.5** — `min` and `max` (float types and `I32x4`/`I32x8`). On floats
the result is a NaN if either lane is one, and for `-0.0` and `0.0` `min` is
`-0.0` and `max` is `0.0`, whatever the order of the operands. This is the
definition both ARM64's `fmin` and `fmax` give and the one an x86-64 sequence
can match; it differs from `Ord`'s total order (type.num.11). *(ADR 1014)*

**std.simd.6** — The integer types have `bit_and`, `bit_or`, `bit_xor` and
`bit_not` (`expr.bit.1`), and `shl(k)` and `shr(k)`, which shift every lane by
`k` bits as the lane's width: `shl` drops the bits that leave the lane and `shr`
copies the sign bit. A count outside `0..32` (`I32x4`, `I32x8`) or `0..64`
(`I64x2`, `I64x4`) traps with `std.simd.6`. *(ADR 1014)*

**std.simd.7** — The comparisons `eq`, `ne`, `lt`, `le`, `gt` and `ge` return a
mask: an integer vector of the same lane count whose lane is all ones (`-1`)
where the comparison holds and zero where it does not. The mask of `F32x4` is
`I32x4`, of `F64x2` is `I64x2`, of `F32x8` is `I32x8`, of `F64x4` is `I64x4`, and
an integer type's own. A comparison with a NaN is false, except `ne`.
`a.blend(b, m)` has lane `i` of `b` where lane `i` of `m` is not zero, else
of `a`. *(ADR 1014)*

**std.simd.8** — `v.sum()` adds the lanes as a balanced tree, so the result is
fixed: lanes `0` and `1`, `2` and `3`, and so on, then those sums in pairs. A
float sum is rounded at every addition; an integer sum wraps. *(ADR 1014)*

**std.simd.9** — The module is plain AIL: it needs no `unsafe`, and a program
that uses it builds on every target. There is no `asm fn` (ADR 1014): the
vector unit is reached only through these types. *(ADR 1014)*

```ail rules=std.simd.1,std.simd.2,std.simd.3,std.simd.4,std.simd.8,std.simd.9
use std.simd

fn main()
    a := simd.F32x4.load([1.0.to_f32(), 2.0.to_f32(), 3.0.to_f32(), 4.0.to_f32()], 0)
    b := simd.F32x4.splat(0.5.to_f32())
    c := a.mul(b).add(simd.F32x4.splat(1.0.to_f32()))
    print(c.to_list())      # [1.5, 2.0, 2.5, 3.0]
    print(c.lane(3))        # 3.0
    print(c.sum())          # 9.0
```

```ail rules=std.simd.5,std.simd.7
use std.simd

fn main()
    a := simd.F64x2.load([1.0, 5.0], 0)
    b := simd.F64x2.load([4.0, 2.0], 0)
    m := a.lt(b)
    print(m.to_list())              # [-1, 0]
    print(a.blend(b, m).to_list())  # [4.0, 5.0]
    print(a.max(b).to_list())       # [4.0, 5.0]
```

```ail rules=std.simd.6
use std.simd

fn main()
    v := simd.I32x4.load([1.to_i32(), 2.to_i32(), (0 - 8).to_i32(), 2147483647.to_i32()], 0)
    print(v.shl(1).to_list())   # [2, 4, -16, -2]
    print(v.shr(1).to_list())   # [0, 1, -4, 1073741823]
    print(v.add(v).to_list())   # [2, 4, -16, -2]: wraps
```

## Rejected alternatives

- **A single generic `Vec[T, N]`.** Needs const generics in a std module
  (ADR 0954) and a type per width anyway for the vector unit; named types give
  the checker and the reader the lane count and type at once.
- **Operators (`a + b`).** `Add` and its kin are not implementable yet
  (`trait.op.1`); the methods take the same tokens as the operator once they
  are.
- **`fma`.** A fused multiply-add has no scalar twin in the language to define it
  by, so it waits for one (it must not change the result between targets).
- **Lanes taken from the platform's NaN or `-0.0` behaviour.** The result of
  `min` would then differ between ARM64 and x86-64 (std.simd.5).
