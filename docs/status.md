# Project status

_Last updated: 2026-11-20_

**Current stage:** 2 — native self-hosting. The Rust bootstrap and interpreter are
deleted ([ADR 0904](decisions/0904-rust-bootstrap-deleted.md)); the compiler, checker
and tools are written in AIL and `ail` builds itself from the published seed. The
Stage 1 core design is complete ([ADR 0086](decisions/0086-finish-core-design-before-stage-2.md)).
The Mac gate ([ADR 0842](decisions/0842-mac-first-gate.md)) gates every change;
Linux and Windows are tested on the designer's VMs, and the full gate (the same
suite list, `tools/gate/suites.txt`) must pass on Windows before every release ([ADR 0925](decisions/0925-windows-release-gate.md)).
v0.1.0 was published on 2026-11-15 (the first public tag; seed trust is set in [ADR 0976](decisions/0976-public-release-and-seed-trust.md) and the freeze in [ADR 1035](decisions/1035-v0-1-0-freeze-and-release-candidate.md)), with [SECURITY.md](../SECURITY.md) and [CONTRIBUTING.md](../CONTRIBUTING.md) at the root; versions and the changelog follow [ADR 1043](decisions/1043-versions-tags-changelog.md). 0.2.0 was released on 2026-11-21 (see "0.2.0" below). Landed 2026-11-08 and 2026-11-09: FLAC decoding and Opus CELT (`std.audio`), the VP9 decoder (`std.video.vp9`), gamepad input, `try_recv`/`recv_for`, coverage-guided `ail test --fuzz`, `ail test --mutate`, `ail context` and `ail infer --contracts` (all gated in the `agent_tools` suite). See
[language-card.md](language-card.md) for the supported subset, and [roadmap.md](roadmap.md) for what comes next.

## What is implemented

### Milestones (2026-10-04 to 2026-10-05)

All verified on Linux x86-64 and macOS ARM64.

1. `./ail run examples/hello.ail` prints `Hello, world!`.
2. `examples/gradebook.ail`: structs, enums, methods, `match`, loops, lists, `mut`, interpolation.
3. `examples/commands.ail`: error types, `T ! E` and `!T`, `?`, `else`, optionals, variants with data, `for mut`, error reports from `main`; then if-binding conditions (ADR 0125).
4. `examples/shapes.ail`: traits, `impl`, default methods, `any Trait`, generics, inference, `Eq`, `Ord`, `ToStr` (ADRs 0126–0129).
5. `examples/interp.ail`, `json.ail`, `sheet.ail` (500–800 lines each) with output identical to their Python versions: floats, `char`, maps and sets, multi-line and raw strings, literal and or-patterns, constants, `! E` results, statement `else` (ADRs 0130–0140).
6. Python parity: implicit `self`, positional and shorthand constructor arguments, empty literals typed by first use (ADRs 0141–0143); the three examples are 1.5% above Python in tokens.

- Generators and user iteration (ADR 1073, expr.yield.1-4, expr.iter.1-3; supersedes ADR 0965): `yield` in a function returning the prelude's unique `Seq[T]`, lowered natively to a resume function over a closure-object frame (only values live across a `yield` are kept there); `for` over any type with `next(mut self) T?`; lazy adapters `map`, `filter`, `take_while`, `take`, `skip`, `enumerate`, `zip`, `chain`, and `collect`, `count`.
- `select` over channels (ADR 1102, conc.select.2-6): arms `v := ch.recv() =>`, `ch.send(x) =>`, `after ms =>` and `closed =>` over channels of any element types; the first ready arm in source order runs; `closed` is required with a receive arm. Native: `compiler/mir/lower_select.ail` and `compiler/rt/native/chansel.ail`. `select` is a keyword.
- Time zones (ADR 0924): AIL ships the IANA tz database, so zones answer the same on every OS, Windows included; the Windows system zone maps to its IANA name (ADR 0972).
- Data-range guards and interchange (ADR 0941, native.bce.12-13): a scan of the lists a nest only reads bounds their elements, so the nest's overflow checks go, and `for j: s := s0; for k: s += t; row.push(s)` runs as k outside, j inside, behind a guard; bit-identical for `int` and `float`.
- Elements in registers across a loop (ADR 1079, native.promote.1): a counted innermost loop keeps the elements it assigns at an index it doesn't change in registers, loaded before and stored after, when every other access is provably elsewhere.
- One guard test per list (ADR 1080, native.bce.10): an index the counted loops around keep within constants joins the list's single `K < len` test instead of adding its own.
- Dominated checks and field alias classes (ADR 1050, native.fwd.1-3): load forwarding carries loads and passed bounds checks across joins, a field store forgets only its offset, and a `get`/`set` whose list and index already passed a check on every path, with nothing between that can shorten a list, loses its check.
- Overflow facts (ADR 0994, native.bce.14): in loops of any shape, a checked `x + 1` after `x < y`, index sums after a checked index use, and `a + l` (with `l` stepping from 0) bounded on every path back lose their checks; lzr's match loop drops two `jo` per pass.
- Known list lengths (ADR 1061, native.bce.15): a list built by a constant-count comprehension or a literal and only read after has a constant length; `len` folds and index checks compare to an immediate (vm's `st[sp]`).
- Multi-exit loop versioning (ADR 1062, native.bce.16): counted loops that also leave through `and` terms, `break` or `return` are versioned, and `xs[a + i]` with `a` fixed loses its bounds and overflow checks behind a guard; `AIL_OPT_OFF=mexit` turns the first off.
- Function-wide value ranges (ADR 1063, native.range.1-3): fold.ail asks one interval analysis per function (constants, lengths, masks, shifts, `%`, bytes, dominating comparisons, widened loop values) to drop overflow, division and shift checks, fold decided comparisons and mark non-negative division by 2^k; `AIL_OPT_OFF=vrange` turns it off.
- Branch-free selects (ADR 1141, native.select.1-2): a branch with small integer arms that rejoin becomes both arms and `csel`/`csinc` or `cmov`; checked arithmetic runs unchecked only inside a range guard, else the original checked branch runs; `x / 2^k` after `x % 2^j == 0` is a shift; `AIL_OPT_OFF=select` turns it off.

### Language (2026-10-20 batch)

- **Strings, numbers, collections:** format specifications in interpolation (ADR 0173, resolves OQ-041); sized numeric types, `@inline`, `@deprecated` (ADRs 0194–0197); `str.len()` counts characters, with `byte_len()` (ADR 0208); nested optionals `T??` (ADR 0209); list editing and `str` search methods (ADRs 0214–0215, resolve OQ-047, OQ-048); comprehensions and bare variant patterns (ADRs 0182–0183); key functions `sorted(by: |x| key)`, `take`, `m[k] += v` from zero, `?` caught by an enclosing `else` (ADRs 0250–0255); set `union`, `intersect`, `difference` and `m.push(k, x)` (ADRs 0340–0342); standard modules in scope without `use`, messages on error types, `?` on optionals failing with `Absent`, a one-line `if c then a else b` (ADRs 0277–0280, resolve OQ-071, OQ-072); round-4 syntax candidates measured, no new syntax, pairs in OQ-124 (ADR 0675); tuples (ADR 0791): `(int, str)` types and `(a, b)` literals, `t.0`, `a, b := t`, `for k, v in m`, tuple patterns, `xs.enumerate()`, `zip(a, b)`, elementwise `==`/`<`/hash, JSON arrays, in the interpreter, the bytecode tier and the self-hosted checker (ADRs 0792–0795); native lowering (ADR 0829): a kind-4 struct object per tuple, `t.k`, destructuring, patterns, `==` and `<`, printing, `enumerate`, `zip`; tuples as table keys and sorting a list of tuples are reported as outside the subset.
- **Ownership:** moves checked on every path, `move` parameters and `move self` receivers, `unique` types cleaned up by `Drop`, `ref` cells with exclusivity traps, unique values in lists and maps (ADRs 0190–0193, 0317–0319).
- **Concurrency:** tasks, task groups, channels and mutexes under a deterministic scheduler (ADRs 0186–0189); `for v in ch`, scoped `with m as mut x`, and `[f(x) par for x in xs]` (ADRs 0300–0302); `Atomic[int]`/`Atomic[bool]`, cancellation, and `ail test --schedule=random[:SEED]` (ADRs 0320–0322); cancel trees, cancelled `send`, and `order:` for weaker atomic orderings (ADRs 0351–0352).
- **Parallelism:** `par for` asserts independence and provable conflicts are errors; automatic parallel loops where provable; a thread pool (`ail run --parallel`, `AIL_THREADS`) that falls back to the sequential result; fixed-tree float `sum()`; vectorised independent loops (ADRs 0236–0239, 0246, 0272–0275).
- **Modules and packages:** user modules with `use a.b`, `pub` and qualified access (ADRs 0153–0156); `ail.pkg` manifests, path dependencies by package name, per-dependency capability grants (ADRs 0230–0233, resolves OQ-045, [packages.md](design/packages.md)). Git dependencies are fetched with the system `git` into a read-only cache and pinned in `ail.lock`; `ail pkg update` re-pins (ADRs 0355–0357).
- **Unsafe:** `unsafe` blocks and `unsafe fn`, rejected outside a block, with the `unsafe allow` opt-in in `ail.pkg` and the `unsafe` effect (`unsafe.block.1–5`, ADR 0430). `extern c fn` declarations call C libraries on Linux and macOS through `dlopen` (two register-file trampolines, no libffi), with raw pointer types `*T` and `std.mem` C strings (`ffi.*`, `unsafe.ptr.1`, `unsafe.mem.1–2`, ADRs 0431–0434, `examples/ffi_libc.ail`). Raw pointers have `read`, `write`, `offset` and `is_null`, typed `mem.alloc`, and trap on null, out-of-block and freed access (ADR 0435, `examples/ffi_buffers.ail`). The native backend binds an `extern c fn` outside its libc subset lazily with `dlopen` and `dlsym` (ADR 0870; the subset and `std.mem` are ADR 0844); on Windows it binds with `LoadLibraryA` and `GetProcAddress` and calls with Win64 (ADR 0980). Hardware access for drivers is decided (ADR 0820) and partly built (ADRs 0821–0822: `std.hw` `at`, volatile reads and writes and fences in the interpreter and both checkers); native `*T`, `hw.at`, volatile access and fences build on Linux x86-64 and macOS ARM64 (ADR 0835); port I/O, intrinsics and `@layout(c)` follow. Decided: an `unsafe driver` manifest level unlocks `std.hw` (MMIO, volatile, barriers, port I/O, CPU intrinsics), 64-bit targets only (ADR 0820; free-form asm is OQ-137).
- **Effects and contracts:** inferred effect sets, `@pure`, compile-time `ail run --deny` (ADRs 0163–0165) and `--allow LIST`, scoped capabilities for paths, hosts, programs and variables checked at run time (`eff.allow.1-9`, `compiler/rt/native/policy.ail`, ADR 1072; written 2026-11-12, unbuilt until its gate run), `ail new` projects start with `caps fs=.,env,clock,random`, so their runs are deny-by-default (`tool.new.6`, `eff.allow.12`, ADR 1195; written 2026-11-26, unbuilt until its gate run), a dropped value of a call with no effect is an error (ADR 1082); a block may end with `e else return ...` (ADR 1095); `requires`, `ensures`, `old(e)`, trait-method contract inheritance and struct `invariant`, checked at run time (ADRs 0210–0213, 0303–0305).
- **Compile time and reflection:** four compiler tiers and compile-time functions (`ct.const.1–3`), derive generators, `TypeInfo`, `ail api --expanded`, and the `ToJson`/`FromJson` derives with path-naming failures (ADRs 0222–0229, 0306–0309, 0343), generic `FromJson` through bounds and a derivable `Default` (ADR 0350).
- **Interpreter speed:** fast paths and fast hashing (ADRs 0175–0176, 0219–0221, 0297, 0332–0334): interp and loops at parity with CPython, the front end 1.2–1.3x faster; no on-disk cache yet (ADR 0333). A bytecode tier is in progress (ADR 0359, designer's decision; design ADR 0361): slice 1 runs `loops` 1.8x faster than the walker; `./ail selftest` compares both tiers on every program and the fuzzer (ADR 0362); slice 3 compiles method and trait calls, construction, `match`, interpolation and `?` (ADR 0363), so `loops` runs at 0.52x of CPython's time and `interp` at 0.81x, with 99% of the tier's instructions native; run limits, coverage and `--trace` run on the tier too (ADR 0364). Lists of `int`, `float` and `bool` are stored packed in the interpreter (ADR 0760): sieve 0.59 s to 0.21 s, 30 bytes to under 1 byte per flag. Numbers: [interpreter-performance.md](design/interpreter-performance.md), `tools/perfbench/run.sh`.

### Native runtime (batch 2, lane 122)

`compiler/rt/rt.ail`: the native runtime in AIL, tested under the interpreter on a byte-addressed machine model: integer and float text byte-identical to the interpreter (checked on 2,400 random floats and the edge cases), string and list objects, bump allocator, buffered `print`, trap records (ADRs 0404–0409; ABI in [design/native-abi.md](design/native-abi.md)). Not yet: real syscalls and entry point (need lane 120's encoders and lane 126's raw pointers), the collector, frame metadata for trace parity.

### Native heap and collector (lane 171)

`compiler/rt/native/heap.ail`, `gc.ail`: `rt.alloc(n, kind)` with a header word, a heap of 16,960-byte pages (ADR 1158; a whole page plus nine cache lines, was one, so a table's rows spread over the cache sets; ADR 0562 amendment) with size-class free lists, and a stop-the-world conservative mark-sweep collector that runs when the bytes allocated since the last collection pass `max(16 MiB, 2 x live bytes)` (ADR 0564 amendments). Peak resident size is about three times the live data: `binarytrees 20` runs in 80 MiB and 10 GB of short-lived lists in 16 MiB (Linux x86-64, ADR 0564). Tests: `tests/native/run/gc_*.ail` (x86-64 and ARM64 under qemu, also with a collection every 4 KiB), `tests/native/heavy/`. Not yet: precise stack maps, a generational collector.

Heap goal and page return (ADR 1187, `heap_goal.ail`): the next collection comes after `live x slack` bytes (slack 1, floor 4 MiB; both widen to the old 3 and 32 MiB only while collecting takes over 6% of recent run time), and after a sweep free runs above what the next cycle needs go back with `madvise` (macOS, Linux; Windows keeps them). Test `gc_give_back`.

Sweep of unreached pages (ADR 1165): the marker sets a byte per page a pointer reached (`H_PMARK`), and `gc_sweep` frees small pages without one unread. Test `gc_dead_pages`. ail-linux (2026-11-18, against main 832e86a1, with the lane's split and read_line changes): `fields` 2.070 s to 1.119 s (C twin 1.113 s), `readline` 0.354 s to 0.187 s (C twin 0.209 s). Not yet gated.

Text fast paths (ADR 1170): `s.to_float() else` calls `rt.str_float_try` (the number, or a marker NaN compared by bits; `compiler/mir/lower_tofloat.ail`), with no box and no `parse_ok`; `str_split1` takes separators from an exact mark word. Tests `str_to_float_else`, `str_split_marks`. Not yet gated.

### Tooling

- **Semantic API:** diagnostics schema v1 (ADR 0145), `ail explain` covering every emitted rule (ADRs 0146, 0335), typed holes `todo` (ADR 0147), `ail api` with ids, references, doc comments, contracts and effects (ADRs 0150–0152, 0213), `ail api --locals|--type|--refs`, `--card` and package directories (ADRs 0258–0261, 0310–0311, 0325–0327), `ail check --errors` (ADR 0286), `ail effects`, and `ail fix` with anchored fixes for 150 of 250 corpus programs (ADRs 0202–0205, 0264, 0285, 0335). Foreign syntax is reported once with a help (ADR 0262). See [semantic-api.md](design/semantic-api.md).
- **Semantic diff:** `ail diff OLD NEW` and `--rev REV PATH`: declarations added, removed and changed, diagnostics, test outcomes (ADR 0396).
- **`ail ask`:** `ail ask PROGRAM QUESTION...` answers who writes or reads a field, what calls a function, what it calls, which effects reach it and who uses a type, from the checker's graph (`compiler/api/ask.ail`, api.ask.1-6; ADR 0881). Native only; its spec examples (`tool=ask`) run in the gate's `spec` suite.
- **Change certificate:** `ail verify --diff [--rev REV] [--mutate [--max N]] --attest OUT FILE` writes the verify report (`checked` static check, `contracts` from `ail prove`, `tested` with a state of passed, failed, none-ran, could-not-run or not-tested, `unverified`, `failures`) with the base commit, the hash of each changed file, the compiler version, the environment (host and run-time settings), a digest of the program's inputs and the mutation survivors in the changed functions as one JSON object (`cert` 2); `ail verify --check CERT` re-runs it and exits 1 on any difference (`tools/verify/verify.ail`, verify.run.1-6, verify.cert.1-4; ADRs 1052, 1116). Unsigned. Gated by the `cert` suite (Mac, Linux and Windows), which changes each input in turn. `ail task finish` writes it to `.ail/cert.json` and names it (task.finish.3, ADR 1046).
- **One-call lookup (ADR 1177):** `ail ask NAME...` (with or without `std`) prints each named function or method with its rule's sentences and example lines, and answers other languages' names from the checker's table (api.find.9, api.ask.9, `compiler/api/findname.ail`); `ail ask PROGRAM` takes questions in any common form and adds `tests` and `where` (api.ask.7-8); an unknown command names the one meant (tool.help.4). Not built or gated in the cloud; the Mac gate decides.
- **`ail card` and `ail ask std`:** `ail card [TOPIC]` prints the core card (`docs/language-card-core.md`), a section of the full card or a std module's signatures; `ail ask std WORDS...` and `--sig` rank std functions from the spec (`compiler/api/find.ail`, `cardcmd.ail`, api.find.1-4, tool.card.1-3; ADR 1051). Native only; its spec examples (`tool=card`) run in the gate's `spec` suite.
- **`ail context`:** `ail context PROGRAM SYMBOL [--budget N] [--json]` prints the signature, body, effects, callees, callers, types, tests and cited spec rules that an edit to one function needs, cut to a token budget (`compiler/api/context.ail`, api.ctx.1-7; ADR 1020). Native only. Gated by the `agent_tools` suite.
- **`ail attach` on the three hosts:** program and client agree on the discovery directory on Windows (`%TEMP%`), and the listener stops when its window closes (`attach.wire.1`, `attach.wire.7`, `attach.cli.1`; ADR 1045). `tests/cases/std_attach_listen` drives the listener over loopback with a host written in AIL.
- **`ail review`:** `ail review BASE..HEAD [PATH] [--budget N] [--json] [--deny-new]` prints a change by meaning, in one budgeted report: new capabilities and effect changes, the public API change, changed contracts, performance remarks (a hook for ADR 1021) and changed functions no test reaches (`compiler/api/review.ail`, api.rev.1-11; ADR 1024, which builds ADR 0894). Native only. Gated by the `agent_tools` suite.
- **`ail infer --contracts`:** `ail infer --contracts FN FILE [--apply] [--min N] [--cases N] [--json]` runs the tests of FILE against a recording copy of FN and proposes at most 3 `requires`/`ensures` lines every call satisfied, as an `ail edit` patch; `--apply` writes them (`tools/infer/infer.ail`, infer.cand.1-6, infer.out.1-4; ADR 1023). Gated by the `agent_tools` suite.
- **Proved contracts:** the checker proves a `requires` at a same-file call of a top-level function, and an `ensures` at every return, from interval and difference facts (loop bounds, `if` guards, the function's own `requires`, immutable bindings, callee `ensures`); the lowering leaves the proved checks out, except under `--trace` and with `AIL_OPT_OFF=prove`. `ail prove [--json] FILE|DIR` lists each check as proved or checked (`compiler/check/prove.ail`, contract.prove.1-3, prove.cmd.1-2; ADR 1055). Gated by the `contracts` suite, which runs every contract case with and without proving.
- **Probes:** `ail run --at FILE:LINE --show a,b` prints those variables each time a statement starts on that line, natively and over `--replay` (`compiler/mir/lower_probe.ail`, probe.run.1-4; ADR 0921, wishlist 7.5). Gated by the `agent_tools` suite, natively and over `--replay`.
- **`ail task`:** `start`, `status`, `verify`, `finish` and `abort` sequence one change over `ail ask --affected`, `ail check` and `ail test --affected`, with a recorded base and a `next` in every answer (`tools/ailtask/ailtask.ail`, task.state.1-task.out.1; ADR 0917). Every `verify` adds a line to `.ail/task-log.jsonl`; `task log` and `finish --json` summarise it (task.log.1-3; ADR 1048). `ail check --fix FILE` applies the safe fixes, then checks (fix.check.1-2; ADR 1047). Plain `ail check`, `build`, `run` and `test` write only the certain fixes of the root file's errors and go on; `--no-fix` or `AIL_FIX=0` turns that off (fix.auto.1-3; ADR 1130). MCP tools for it follow the compiler serving MCP.
- **`ail try`:** applies `ail edit` patch sets to scratch copies, runs check and tests on each and prints one verdict line per set; `--apply` writes only a clean single set (`tools/ailtry/ailtry.ail`, try.in.1-try.apply.2; ADR 0893). Overlay form and the `ail_try` MCP tool are not built yet.
- **Bare commands:** `ail check`, `run`, `test` and `build` with no argument act on the package in the current directory; `ail test DIR` and `ail build DIR` work; `assert a == b` and `Num(int)` get their own diagnostics ([ADR 1185](decisions/1185-bare-commands-mean-the-package-here.md)). Not in `ail.ps1` yet.
- **`ail eval`:** `ail eval PART...` prints each expression's value and type from one scratch `main`; a binding or `use` part sets up, a trap or a diagnostic names its part (`tools/aileval/aileval.ail`, eval.*, [ADR 1184](decisions/1184-ail-eval.md)). Written, not yet gated.
- **`ail mv`:** `ail mv [--dry-run] [--in DIR] NAME... MODULE` moves functions, constants and types into a module, makes the module's first file when it has none, and keeps `pub`, qualifiers and `use` lines right; all or nothing (`tools/ailmv/ailmv.ail` over the `move` edit with `"ids"`; [ADR 1196](decisions/1196-ail-mv.md)).
- **`ail perf FILE`:** builds the program with a counter at each statement, runs it and prints the ten functions and ten lines that ran the most statements (`tools/ailperf/ailperf.ail`, `AIL_INSTRUMENT=counts`; [ADR 1186](decisions/1186-ail-perf-run-counts.md)). Counts, not time; not in `ail.ps1` yet.
- **`ail merge`:** a three-way merge by declaration and a git merge driver: branches that change different functions never conflict, a function changed on both sides is merged by line, and a true conflict is one hunk with the base; `--check` checks the merge and reports errors neither side had as semantic conflicts, for three files or two branches (`tools/ailmerge/ailmerge.ail`, merge.split.1-merge.check.4; ADR 1019). No gate suite runs it yet (0.2).
- **`ail mcp`:** the compiler's 23 tools (`ail_check`, `ail_test`, `ail_ask`, `ail_impact`, `ail_verify`, `ail_context`, `ail_edit`, `ail_fix`, `ail_explain`, `ail_api`, `ail_review`, `ail_card`, `ail_find`, `ail_try`, `ail_prove`, `ail_infer`, `ail_merge_check`, `ail_verify_check`, `task_*`) as an MCP server on stdio (`tools/ailmcp/ailmcp.ail`, mcp.proto.1-mcp.call.4, mcp.tools.3; ADR 0918; `initialize` sends the kit lessons as `instructions`, ADR 1137). Warm: direct native calls and a memo of unchanged read-only calls (mcp.warm.1-4, ADR 1056; `tools/ailmcp/bench.sh`). Not `ail serve --mcp` (ADR 0892, still Proposed).
- **`ail lsp`:** a language server on stdio (`tools/ailsp/ailsp.ail`, lsp.proto.1-lsp.pos.1; ADR 0966): diagnostics with rule ids as codes, hover, definition, references, document symbols, completion, rename and code actions (quick fixes and fix-all) from `ail check --json` and `ail api`, with unsaved buffers overlaid. The `agent_tools` suite drives real sessions for completion, rename and code actions (lsp.complete.1-lsp.action.2). `tools/vscode/` is a VS Code extension (TextMate grammar and an `ail lsp` client); not published.
- **`ail sanitize`:** runs a program or its tests on the fixed schedule and N seeded random schedules and reports any run whose result differs, as JSON with the replay seed (`tools/ailsan/ailsan.ail`, san.sched.1-2; ADR 0967). Gated by the `agent_tools` suite (the schedule check). The unsafe-race check is designed in the ADR, not built; the leak report is below.
- **`ail leak`:** `AIL_LEAK` makes the collector mark root by root and count bytes by kind and by root; `ail leak [--json] [--all] FILE` reports growth across collections and the roots that hold it (`compiler/rt/native/leak.ail`, san.leak.1-4; ADR 0969). Gated by the `agent_tools` suite. Roots are slot numbers until source names exist (ADR 0947).
- **Fuzzing user code:** `ail test --fuzz NAME [--time MS] [--corpus DIR] FILE` runs a property test on mutated inputs, keeps those that reach a new statement (the native `lines` instrumentation), shrinks the first failure and stores corpus and crashes as files (test.fuzz.1-5; ADR 1015). One process per input; gated by the `agent_tools` suite.
- **Edit oracle:** a plain `ail test FILE` on a file that differs from git's `HEAD` (or `--against OLD`) builds both versions, calls the changed pure functions and their pure callers with the same generated inputs and prints `changed behaviour: f(x: 0) was 1, now traps (...)` or `same behaviour: NAMES`; information only, `--no-oracle` turns it off (test.oracle.1-6, api.impact.7; ADR 1189). Free functions of the file only; gated by `Gate.edit_oracle` in the `diff` suite.
- **Mutation testing:** `ail test --mutate [--max N] FILE` runs the tests, then on each mutant of the reached lines (operators, constants, `true`/`false`, `not`, branch conditions; at most `--max`, default 50, spread evenly) and reports the survivors as `survived FILE:LINE: CHANGE (in FN)` with a score; exit 1 when one survived (test.mutate.1-5; ADR 1022). One build per mutant; gated by the `agent_tools` suite.
- **Contracts checked by tools:** `ail test --contracts FILE` fuzzes every function's `requires`/`ensures` with generated inputs and reports the smallest failing input (contract.fuzz.1-3; ADR 0868 item 5). Native only; no static proof yet (OQ-060 (b)).
- **API diff:** `ail api --diff OLD NEW` and `--rev REV PATH`: added, removed and changed public declarations with `breaking:` marked (ADRs 0729-0731).
- **Structured edits:** `ail edit PATH < EDITS`: replace a body or declaration, insert, delete, rename across the package, add an import; formatted and checked (ADR 0397). Compact hunks under a declaration name, `--test`, and `ail diff` body hunks (ADR 0399). Refactors `change_sig` (every call follows), `extract` (lines into a new function, parameters from the checker's locals) and `move` (to another module, qualifiers and `use` lines follow), edit.op.8-10 (ADR 1054).
- **Run and trace:** `ail run --trace`, `--watch NAME` (on the bytecode tier, ADR 0471), trap snapshots, `--timeout`, `--max-memory`, `--max-steps` (ADRs 0265–0268, 0288–0290, 0326).
- **Token budgets:** `--budget [N]` and `--from K` on every command: most severe records first, a note counting the rest (ADR 0394); records past the first are one line when the whole output does not fit, and the best-ranked are expanded while the budget lasts (budget.out.7, ADR 0868 item 6).
- **Tests:** `@test`, `assert`, `ail test` (ADRs 0167–0168); `ail test --update` rewrites stale literal expectations, `# =>` lines and `.out` files (ADR 0395); `ail run --record R` / `--replay R` and `ail test --record R` repeat a run or a failed test from its recorded effects (ADR 0398); property tests with `--cases`, `--seed`, shrinking; doc examples as tests (ADRs 0198–0201); `--coverage`, `--trace`.
- **Formatter:** `ail fmt` (ADRs 0169–0170) with chained-call lines, own-line attributes and long-line splitting (ADRs 0323–0324, 0346–0347); examples and test cases are canonical.
- **Public corpus:** `corpus/` holds 300 programs with Python twins and expected output (set `core`); later sets go in `corpus/sets/SET/`; the mistakes pairs are published from `tests/mistakes/` with `corpus/mistakes/why.tsv`; `tools/corpus/corpus.py` checks every file and the gate suites `corpus` and `corpus_sets` build and run each program ([ADR 1174](decisions/1174-public-corpus-layout.md)).
- **Benchmarks:** `tools/tokbench` (tokens), `tools/perfbench` (speed), and the agent-tool corpus of ten programs with Python twins, 5.7% under Python in tokens ([program-measurements-r5.md](design/program-measurements-r5.md), [r8](design/program-measurements-r8.md); ADRs 0217–0218, 0337). One command builds two revisions and prints the before/after table for tokens and speed: [measurements.md](design/measurements.md), `tools/bench/run.sh` (ADR 0492). Round three adds ten programs on today's library, 14.6% over Python in total; the gaps are dates, bit operators, bytes and tuples ([program-measurements-agent-r3.md](design/program-measurements-agent-r3.md); ADR 0477).
- **Conformance and fuzzing:** the `spec` gate suite (`tools/gate/spec.ail`) checks every `ail` block in `docs/spec/`, the quick reference and the language card (ADRs 0172, 0174, 0276); the fuzz and differential harness `tools/fuzz/run.sh` runs a 200-program smoke inside `./ail selftest` (ADRs 0269–0271). The tool fuzz (`tools/fuzz/tool_fuzz.ail`, gate suite `toolfuzz`, ADR 1194) checks what `ail ask`, the edit impact, `ail test --affected`, `ail verify`, `ail diff` and the fixes report against generated programs with a known call graph and against real runs. Module fuzzers (`tests/fuzz/modules/`, one template per module, ADR 0461) run in the same selftest and in `ail selftest --fuzz N [SEED]`; their first finding was `parse_json("1e999")` printing `inf` (ADR 0464). `tools/coverage/rules.py` lists spec rules no test names ([rule-coverage.md](design/rule-coverage.md), ADR 0463). `tools/perfbench/run.sh --all` is the drag race against native AIL, C and Python (ADR 0460, [drag-race.md](design/drag-race.md)). `docs/language-card.md` is the whole language within 16,000 tokens (ADR 1110).
