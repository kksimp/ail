## What is implemented

### Milestones (2026-10-04 to 2026-10-05)

All verified on Linux x86-64 and macOS ARM64.

1. `./ail run examples/hello.ail` prints `Hello, world!`.
2. `examples/gradebook.ail`: structs, enums, methods, `match`, loops, lists, `mut`, interpolation.
3. `examples/commands.ail`: error types, `T ! E` and `!T`, `?`, `else`, optionals, variants with data, `for mut`, error reports from `main`; then if-binding conditions (ADR 0125).
4. `examples/shapes.ail`: traits, `impl`, default methods, `any Trait`, generics, inference, `Eq`, `Ord`, `ToStr` (ADRs 0126–0129).
5. `examples/interp.ail`, `json.ail`, `sheet.ail` (500–800 lines each) with output identical to their Python versions: floats, `char`, maps and sets, multi-line and raw strings, literal and or-patterns, constants, `! E` results, statement `else` (ADRs 0130–0140).
6. Python parity: implicit `self`, positional and shorthand constructor arguments, empty literals typed by first use (ADRs 0141–0143); the three examples are 1.5% above Python in tokens.

### Stage 3: self-hosting (started 2026-10-20)

- `ail api --tokens` and `ail api --ast [--program]` print the Rust lexer's tokens and parser's tree, the targets the AIL front end is compared with (ADR 0371); a name is letters, ASCII digits and `_` (ADR 0372).
- `compiler/syntax/`: the lexer and parser in AIL, identical to `ail api --tokens` and `ail api --ast` on all 770 repository files; diagnostics are rule and position (ADR 0373).
- `compiler/ast/`: the syntax tree in AIL, with derived JSON as the shape of `ail api --ast` (ADR 0376).
- `compiler/check/`: the checker in AIL, ported pass for pass (ADR 0377). Slice 1 (declarations) agrees with `ail check` on every corpus program; the selftest `self_hosted_check` holds it there. Progress and agreement rates: [self-hosting-status.md](design/self-hosting-status.md).
- `compiler/mir/`: the native backend's MIR in AIL (ADR 0384): flat instructions in SSA with block parameters, built from the AIL syntax tree by Braun et al.'s construction, cleaned up and verified; `ail run compiler mir FILE` prints it. The native subset is numbers, strings, lists and free functions, enough for eleven perfbench programs (ADR 0390, native.subset.1, [23-native.md](spec/23-native.md)); the ABI is in [native-abi.md](design/native-abi.md).
- `compiler/x64/`, `compiler/codegen/`, `compiler/obj/`, `compiler/rt/native/`: x86-64 code generation (ADR 0385), linear-scan allocation (ADR 0386), static ELF executables with the runtime compiled from AIL (ADR 0387). `ail build FILE` works on Linux x86-64 (native.build.3); `bootstrap/tests/native.rs` builds each `tests/native/run/` program and compares it with `ail run`.
- `compiler/a64/`, `compiler/obj/macho.ail`: ARM64 code generation (ADR 0388) and signed Mach-O executables (ADR 0389); `ail build --target aarch64-linux|aarch64-macos`. Linux ARM64 is tested under qemu where installed; macOS ARM64 in the designer's gate.
- Native drag race (ADR 0390): eleven perfbench programs build natively and match the interpreter byte for byte; times against `clang -O2`, `gcc -O2` and Python, and the compiler's own speed, are in [native-performance.md](design/native-performance.md). First optimisations (ADR 0391): lifetime holes, MIR folding and CSE, inlining of small leaf functions, inline `push`, byte-sized `List[bool]`, ELF symbols.

### Language (2026-10-20 batch)

- **Strings, numbers, collections:** format specifications in interpolation (ADR 0173, resolves OQ-041); sized numeric types, `@inline`, `@deprecated` (ADRs 0194–0197); `str.len()` counts characters, with `byte_len()` (ADR 0208); nested optionals `T??` (ADR 0209); list editing and `str` search methods (ADRs 0214–0215, resolve OQ-047, OQ-048); comprehensions and bare variant patterns (ADRs 0182–0183); key functions `sorted(by: |x| key)`, `take`, `m[k] += v` from zero, `?` caught by an enclosing `else` (ADRs 0250–0255); set `union`, `intersect`, `difference` and `m.push(k, x)` (ADRs 0340–0342); standard modules in scope without `use`, messages on error types, `?` on optionals failing with `Absent`, a one-line `if c then a else b` (ADRs 0277–0280, resolve OQ-071, OQ-072).
- **Ownership:** moves checked on every path, `move` parameters and `move self` receivers, `unique` types cleaned up by `Drop`, `ref` cells with exclusivity traps, unique values in lists and maps (ADRs 0190–0193, 0317–0319).
- **Concurrency:** tasks, task groups, channels and mutexes under a deterministic scheduler (ADRs 0186–0189); `for v in ch`, scoped `with m as mut x`, and `[f(x) par for x in xs]` (ADRs 0300–0302); `Atomic[int]`/`Atomic[bool]`, cancellation, and `ail test --schedule=random[:SEED]` (ADRs 0320–0322); cancel trees, cancelled `send`, and `order:` for weaker atomic orderings (ADRs 0351–0352).
- **Parallelism:** `par for` asserts independence and provable conflicts are errors; automatic parallel loops where provable; a thread pool (`ail run --parallel`, `AIL_THREADS`) that falls back to the sequential result; fixed-tree float `sum()`; vectorised independent loops (ADRs 0236–0239, 0246, 0272–0275).
- **Modules and packages:** user modules with `use a.b`, `pub` and qualified access (ADRs 0153–0156); `ail.pkg` manifests, path dependencies by package name, per-dependency capability grants (ADRs 0230–0233, resolves OQ-045, [packages.md](design/packages.md)). Git dependencies are fetched with the system `git` into a read-only cache and pinned in `ail.lock`; `ail pkg update` re-pins (ADRs 0355–0357).
- **Unsafe:** `unsafe` blocks and `unsafe fn`, rejected outside a block, with the `unsafe allow` opt-in in `ail.pkg` and the `unsafe` effect (`unsafe.block.1–5`, ADR 0430). `extern c fn` declarations call C libraries on Linux and macOS through `dlopen` (two register-file trampolines, no libffi), with raw pointer types `*T` and `std.mem` C strings (`ffi.*`, `unsafe.ptr.1`, `unsafe.mem.1–2`, ADRs 0431–0434, `examples/ffi_libc.ail`). Raw pointers have `read`, `write`, `offset` and `is_null`, typed `mem.alloc`, and trap on null, out-of-block and freed access (ADR 0435, `examples/ffi_buffers.ail`). The native-backend hook follows (ADRs 0436–0437).
- **Effects and contracts:** inferred effect sets, `@pure`, compile-time `ail run --deny` (ADRs 0163–0165); `requires`, `ensures`, `old(e)`, trait-method contract inheritance and struct `invariant`, checked at run time (ADRs 0210–0213, 0303–0305).
- **Compile time and reflection:** four compiler tiers and compile-time functions (`ct.const.1–3`), derive generators, `TypeInfo`, `ail api --expanded`, and the `ToJson`/`FromJson` derives with path-naming failures (ADRs 0222–0229, 0306–0309, 0343), generic `FromJson` through bounds and a derivable `Default` (ADR 0350).
- **Interpreter speed:** fast paths and fast hashing (ADRs 0175–0176, 0219–0221, 0297, 0332–0334): interp and loops at parity with CPython, the front end 1.2–1.3x faster; no on-disk cache yet (ADR 0333). A bytecode tier is in progress (ADR 0359, designer's decision; design ADR 0361): slice 1 runs `loops` 1.8x faster than the walker; `./ail selftest` compares both tiers on every program and the fuzzer (ADR 0362); slice 3 compiles method and trait calls, construction, `match`, interpolation and `?` (ADR 0363), so `loops` runs at 0.52x of CPython's time and `interp` at 0.81x, with 99% of the tier's instructions native; run limits, coverage and `--trace` run on the tier too (ADR 0364). Numbers: [interpreter-performance.md](design/interpreter-performance.md), `tools/perfbench/run.sh`.

### Standard library

- `std.json` (`Json`, `parse_json`, `to_text`, typed getters and `set`; ADRs 0161–0162, 0254) and `ToJson`/`FromJson` derives.
- `std.fs` (with `walk`, `glob`, `metadata`, `rename`, `copy`), `env`, `io`, `proc` (input, time limit, `which`), `time`, `path`, and `net` (an HTTP/1.1 client with headers, methods, query and limits, an HTTP/1.1 server with `accept`/`respond`, raw TCP `Listener`/`Conn` and TLS over `Conn`, ADRs 0157–0160, 0253, 0281–0284, 0418–0423) with `https` over an in-house TLS 1.3 client (ADR 0360): constant-time primitives, the handshake, and certificate verification against the platform's roots or `SSL_CERT_FILE` (ADRs 0366–0369, `std.net.5`; [tls-security.md](design/tls-security.md)).
- Windows (ADRs 0504–0506): `std.path` drive roots, glob on `C:\` and `\`, and `std.proc.run` finds `.cmd` and `.bat` through `PATHEXT`. The checklist is [design/windows-status.md](design/windows-status.md); it has not been run on Windows yet.
- `std.time.date` (`Date`, `DateTime` with a zone, millisecond durations, month clamping, ISO 8601 `parse_iso`/`iso()`, strftime-style `format`) written in AIL, and `std.tz`, a TZif and POSIX-rule zone reader for Linux and macOS; Windows reads UTC and fixed offsets only, a cited stub (ADRs 0447–0451).
- `std.fs` (with `walk`, `glob`, `metadata`, `rename`, `copy`), `env`, `io`, `proc` (input, time limit, `which`, streaming children with `start`/`wait`/`kill`, ADRs 0424–0428) with `task.select` over channels, `time`, `path`, and `net` (a small HTTP/1.1 client, ADRs 0157–0160, 0253, 0281–0284) with `https` over an in-house TLS 1.3 client (ADR 0360): constant-time primitives, the handshake, and certificate verification against the platform's roots or `SSL_CERT_FILE` (ADRs 0366–0369, `std.net.5`; [tls-security.md](design/tls-security.md)).
- `std.hash` (`sha256/384/512`, `hmac_sha256`, `crc32`, `hash64`) and `std.compress` (DEFLATE, gzip, zip of a directory), all in-house, checked against system `gzip` and `unzip`; over `bytes` or `str` (ADRs 0442–0446).
- `std.fs` (with `walk`, `glob`, `metadata`, `rename`, `copy`), `env`, `io`, `proc` (input, time limit, `which`), `time`, `path`, and `net` (a small HTTP/1.1 client, ADRs 0157–0160, 0253, 0281–0284) with `https` over an in-house TLS 1.3 client (ADR 0360): constant-time primitives, the handshake, and certificate verification against the platform's roots or `SSL_CERT_FILE` (ADRs 0366–0369, `std.net.5`; [tls-security.md](design/tls-security.md)).
- `std.regex`: linear-time Pike VM, RE2 syntax subset (classes, anchors, lazy and counted repetition, named groups, flags, a documented Unicode subset), `compile`/`is_match`/`find`/`find_all`/`captures`/`replace`/`split`/`escape`, 360+ vectors and property tests; no backreferences or lookaround; `re"..."` literal and method syntax measured and deferred (ADRs 0438–0441).
- `bytes` (ADRs 0412–0415): an immutable sequence of `u8` with the literal `b"..."`, indexing, slices, `+`, iteration, strict and lossy text conversion, hex and base64, and `fs.read_bytes`/`write_bytes`/`append_bytes` and `io.read_bytes`; `net` bodies and raw TCP (`get_bytes`, `respond_bytes`, `Conn.read_bytes`) and `proc.run_bytes` (ADRs 0416–0417).
- `std.random` and `ail run --deterministic` with `--seed` (ADRs 0206–0207, resolve OQ-043, OQ-044, OQ-046).
- `std.tensor`: value-typed `Tensor[int|float]` with elementwise operators (`/` on floats), reductions, `matmul`, `transpose`, activations `relu`, `sigmoid`, `tanh` (ADR 0507); AVX2, NEON or scalar kernels chosen at run time with one specified summation order, `matmul` on the thread pool; device backends designed only (ADRs 0328–0330, 0344–0345, 0507, 0247). Still open in the CPU slice: `f32`, `conv2d`, indexing and slicing, broadcasting, unary `-`, operator fusion.
- `std.ui`: a window of monospace text cells with keys, resize, mouse, scroll, clipboard, modifiers, font sizes, text styles and colors; capability `ui` (ADRs 0177–0179, 0240, 0242–0243, 0294; [gui-path.md](design/gui-path.md)). `std.ui.widgets`, the first standard module written in AIL (ADRs 0314–0316, `examples/dashboard.ail`).

### Native runtime (batch 2, lane 122)

`compiler/rt/rt.ail`: the native runtime in AIL, tested under the interpreter on a byte-addressed machine model: integer and float text byte-identical to the interpreter (checked on 2,400 random floats and the edge cases), string and list objects, bump allocator, buffered `print`, trap records (ADRs 0404–0409; ABI in [design/native-abi.md](design/native-abi.md)). Not yet: real syscalls and entry point (need lane 120's encoders and lane 126's raw pointers), the collector, frame metadata for trace parity.

### Editor

`tools/edit/edit.ail`, a code editor written in AIL (ADRs 0180–0181, 0241): a headless, tested core driving `ail check --json`, fixes, `ail explain` and `ail api`, with a `std.ui` window front end. It has completion, hover, find and replace, format on save, tabs, a Ctrl-P picker, a command palette, project search and replace, a file tree, rename through references, themes, an agent panel (info, trace, failure paths, coverage, program card) per-directory session memory, a problems list that stays live, a replace preview with per-row accept, and tests on save (ADRs 0244, 0291–0296, 0312–0313, 0331, 0338–0339, 0353–0354).

`tools/garlic/garlic.ail`, Garlic, a text-mode web browser written in AIL ([garlic-browser.md](design/garlic-browser.md), 2026-10-20): an HTML tokenizer and tree builder, text-cell layout with numbered links, history and find, a `std.ui` window, forms (GET and POST), agent actions (`--do`, `--session`), and a page model agents read (`--json`: roles, names, values, links, changed nodes and the cells each was drawn in). No CSS or JavaScript yet; a JavaScript engine in AIL is a parallel lane.

### PDF reader

`tools/pdf`, a PDF reader, searcher and viewer written in AIL (ADR 0520, [design note](design/pdf-viewer.md)): the text layer from the fonts' Unicode maps with no OCR; xref tables and streams, object streams, repair of damaged tables, Flate/LZW/ASCII85 with predictors, ToUnicode CMaps and encodings; `pdf text`, `grep` (boxes, across line breaks), `json` (the page model for agents), `info` (flags scans), `outline`, `bench`, and a text-cell viewer with search (`--print`, `--json`). Stopgaps until `bytes`: `od` for reads and an inflate in AIL. Not yet: encryption, pixel rendering.
